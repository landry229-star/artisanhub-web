ArtisanHub – Fonctionnalités manquantes et configuration à prévoir

Date de génération : 2026-09-10 | État : checklist de pré-pilote / production

1. Fonctionnalités manquantes avant vraie mise en ligne

Priorité 1 – indispensable avant pilote réel

  • Monitoring et alertes : alertes sur commandes retardées, paiements en échec, reversements / remboursements bloqués, erreurs FedaPay / SMTP / queue, health checks réels, logs centralisés.
  • Sauvegarde / restauration testée : backup DB, backup fichiers uploads, restauration sur environnement de staging, plan de reprise validé.
  • Sécurité admin & journalisation : traçabilité des validations KYC, suspensions, remboursements, réassignations, journal des actions sensibles.
  • Validation des services externes : FedaPay Sandbox / vraie vérification du flux, SMTP réel, WhatsApp/SMS réel, queue worker actif et stable.
  • Tests admin ciblés : validation KYC admin, suspension/réactivation, réassignation livreur, remboursement/reversement admin, export des données.

Priorité 2 – fort recommandé avant élargissement

  • Support admin complet : tickets persistants avec statut, priorité, réponses, SLA, assignation interne, historique de conversations, filtres par utilisateur/commande/statut.
  • Gestion avancée des litiges : motifs de litige, décision avec commentaire, suivi du remboursement / réouverture, pièces jointes ou preuve de livraison.
  • Recherche et filtres admin : par ville, artisan, client, statut, date, export ciblé, recherche textuelle rapide.
  • UX mobile et accessibilité : navigation clavier, contraste, taille de cible, test sur mobile réel.

Priorité 3 – bonne amélioration post-pilote

  • Dashboard Revenus par ville / artisan / service, taux d’acceptation livreur, taux de litige / remboursement, temps moyen de livraison.
  • Automatisations admin Alertes automatiques, relances, regroupement de commandes et anomalies, API d’export plus propre.
  • Exports CSV/Excel/PDF structurés, fichiers nommés et versionnés, historique des exports.

2. Fonctionnalités de produit déjà couvertes dans le code

  • Support client persistant et historique.
  • Commande répétée (recommander un ancien service).
  • Profil client détaillé : quartier, repère, GPS, préférences de notification.
  • Suivi de paiement et justificatifs PDF.
  • Reversement Mobile Money artisan.
  • Blocage serveur si le paiement n’est pas confirmé.
  • Modification des services artisan.
  • Solde et relevé PDF livreur.
  • Journal d’audit admin.
  • Motifs d’annulation / refus.
  • Alertes de commandes en retard.
  • Preuves de livraison par code ou signature.
  • Recherche géographique et gestion des livraisons.
  • Contrat, garantie, réclamation et suivis administratifs.

3. Configuration à prévoir avant mise en ligne

Domaine Configuration nécessaire
Serveur HTTPS, domaine, reverse proxy, sécurité OS, utilisateurs non-root, variables d’env, logs, cron, supervisor, queue workers.
Base de données MySQL/PostgreSQL production, backup automatique, point-in-time restore si nécessaire, connexion sécurisée, permissions minimales.
Fichiers Storage object ou disque persistant pour uploads, KYC, preuves de remise, fichiers sécurisés, rotation et backup.
Email SMTP réel, domaine vérifié, DKIM/SPF/DMARC, templates production, alertes sur échec d’envoi.
SMS / WhatsApp Provider réel, numéros validés, quotas, journal, seuils de sécurité, gestion des erreurs et coûts.
Paiements FedaPay prod ou sandbox réelle, clés API, endpoints de callback, webhooks, vérification des statuts, gestion des remboursements et reversements.
Monitoring Sentry ou équivalent, logs centralisés, métriques de queue, uptime, alertes SMS/email/Slack, dashboard exploitation.
Queue / jobs Supervisor, retry policy, dead-letter logs, jobs longs, délais, vérification du worker actif.
Security rate limiting, CSRF, permissions admin, rôles, journal d’audit, secret rotation, HTTPS strict.
Mobile & accessibilité Test sur vrais appareils, taille des boutons, contraste, navigation clavier, labels, mise en page responsive.

4. Check-list finale de validation avant ouverture réelle

  • Vérifier monitoring, alertes et logs centralisés.
  • Tester backup / restore sur environnement de staging.
  • Valider FedaPay, SMTP, WhatsApp/SMS en production réelle.
  • Tester le flux KYC des profils multiples.
  • Valider les remboursements / reversements.
  • Contrôler les commissions et revenus.
  • Valider la répartition de la charge admin et les exports.
  • Tester le parcours mobile complet et l’accessibilité.
  • Documenter le runbook de reprise et de support.

5. Conclusion

Le cœur du produit est fonctionnel et les usages principaux sont couverts. La vraie difficulté restante n’est pas une fonctionnalité “métier absente” mais l’exploitation, la supervision et la validation des services tiers et de la production.

Le projet est prêt pour un pilote fermé, mais pas encore prêt pour un usage réel grand public sans la configuration opérationnelle et les validations décrites ci-dessus.
