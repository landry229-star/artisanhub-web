ArtisanHub – Version client / chef de projet

Date : 2026-09-10 | Résumé décisionnel

Le produit est aujourd’hui prêt pour un pilote interne ou fermé, mais pas encore prêt pour une mise en ligne publique massive. Le cœur fonctionnel est solide, mais l’exploitation, la supervision et la validation des services externes restent les vrais points bloquants.

1. État du projet

  • Le cœur du produit est fonctionnel : clients, artisans, livreurs, admin, paiements, KYC, preuves de livraison, support, litiges, reversements, suivi des gains.
  • Les parcours critiques sont couverts : commande, validation, livraison, paiement, remboursement, garantie, support, sécurité admin.
  • Le vrai risque n’est pas la fonctionnalité, mais l’exploitation en production : monitoring, sauvegarde, intégrations externes, disponibilité, traçabilité.

2. Ce qui est déjà bien couvert

  • Profil client détaillé avec historique, préférences, adresses, GPS.
  • Support client persistant avec historique de tickets.
  • Commande répétée et re-commande rapide.
  • Reversement Mobile Money artisan.
  • Blocage serveur si le paiement n’est pas confirmé.
  • Modification des services artisan.
  • Solde et relevé PDF pour livreurs.
  • Journal d’audit admin pour la traçabilité des décisions sensibles.
  • Tableau de bord admin plus utile pour le pilotage.

3. Ce qui manque avant vraie ouverture

Priorité 1 – indispensable

  • Monitoring & alertes : alertes sur commandes retardées, paiements ou reversements bloqués, erreurs FedaPay / SMTP / queue, logs centralisés.
  • Sauvegardes et restauration : base de données et uploads, test de restauration, procédures de reprise.
  • Validation externe : SMTP réel, SMS/WhatsApp, FedaPay valide, queue stable.
  • Sécurité admin : journal complet des décisions administratives, traçabilité sur KYC, remboursements et réassignations.

Priorité 2 – recommandé avant élargissement

  • Support admin complet avec SLA, assignation, historique, tri et filtres.
  • Gestion avancée des litiges et pièces jointes.
  • Recherche admin rapide par ville, artisan, client, date et statut.
  • Accessibilité et test réel mobile.

Priorité 3 – améliorations post-pilote

  • Dashboard analytique plus fin : revenus, taux de litige, temps moyen de livraison.
  • Automatisations admin : relances, alertes, anomalies, exports structurés.
  • Historique des exports et nommage versionné des fichiers.

4. Plan de décision

Situation Décision
Pilote interne / fermé OK
Usage public limité après validation de production À condition de valider monitoring + backups + intégrations
Ouverture grand public NON – avant les points de production

5. Conclusion

Le produit est bien avancé et les usages métiers principaux sont présents. La condition clé pour passer à l’étape suivante est la mise en place d’une vraie infrastructure de supervision et de production, pas seulement l’ajout de nouvelles fonctionnalités.

En une phrase : le produit est prêt pour un pilote contrôlé, mais pas encore prêt pour une ouverture réelle sans validation de production.
